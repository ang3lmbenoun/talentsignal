# Number audit — every number a signed-in user sees

**Date:** 2026-11-03 · **Branch:** `main` @ `55ff6e5` · **Mode:** read-only audit (no source file edited; this report is the only file created).

**Scope:** Overview, Signals, Opportunities, Candidates, Packages, Analytics, Clients (+ Client detail), Targeting. Read from the screen components and their `lib/` helpers, not guessed.

**Example values** in the table come from the local demo database as of 2026-11-03 (1,124 opportunities = 307 Greenhouse/GitLab + 817 Lever/Gopuff; 40 fixture candidates; 0 clients; 0 job openings; 0 packages; 0 `sales_pipeline_audit` rows; 3,986 `raw_requisitions` rows). I ran the *real* frontend derivation functions (`basisDerivation.ts`, `clientAggregation.ts`) over the real DB rows with a SELECT-only script to get them. Values marked **(not computed)** come from endpoints I did not execute (`/api/fits/summary`, targeting).

**Rules applied:** a number that carries a trust/provenance rule (n counts, basis, weights version, live / seeded / flagged / stubbed labels) is only ever KEEP, REWORD or MOVE, never REMOVE. No action below touches scoring, weights, thresholds or ranking. "Show the math" = a collapsed per-screen details panel (the pattern the Opportunities card already uses for "Why this score").

Legend for the *Required?* column: **CLAUDE.md** rules cited by number (R4 = no silent assumptions, R5 = heuristic must be transparent/explainable, R6 = trust scenarios mandatory). `06_decisions/NNN` cited by number.

## E. The 10 numbers that confuse users most

1. **Measured basis: 180 vs 155** (D1, rows 14/25/37). Three screens say 180, the Opportunities cards say 155 (and "none" 934 vs 959). Both are labelled "measured", and the basis is the core trust claim.
2. **"Total signals 2,701"** on a dataset of 1,124 postings (rows 2/20, D4). It silently double-counts nested clues and mixes in a "scarcity" that is not counted.
3. **Story of the week: "greenhouse shows 885 long-open"** (row 11). The 885 is mostly Lever rows, and the text attributes it to Greenhouse. This one is factually wrong, not just unclear.
4. **Clients: 0 vs 2 vs 0** (rows 3/32/71, D2). "Active clients 0" on the landing page, "2 client companies" one click away.
5. **Analytics funnel** (row 65). A narrowing funnel whose second stage (2,701) is bigger than the first (1,124), whose third stage is an average, and whose widths are fixed.
6. **"Requisitions Ingested 3,986"** (row 10, D3). It is snapshots; there are 1,124 requisitions.
7. **"62% to review" / "100% role-difficulty signal"** (rows 17/82, D7). A percentage with no denominator that saturates at 100%, under three different names.
8. **Signals: "1,124 of 1,124 have a clue" and "Reposted 0"** (rows 19/21). A figure with no discriminating power, and a zero that means "not observable yet" but reads as "none".
9. **Analytics "Placements this month 0" / "Active pipeline value 0"** (rows 59/64/70). The "this month" is the last month with data, the "value" is a draft count, and a banner describes seeded rows that are not in the database.
10. **Three confidence band systems** (D5, rows 16/34). Overview calls 95% of postings "Good", the ring colours say none reach green or even indigo, and none of the cut-offs are on screen.

Honourable mentions: "Avg candidate fit" meaning "best candidate" (row 5); "Available now" matching any text containing "now" (row 49); "Showing 1,124 of 1,124" next to "Load more (50 of 1,124)" (row 47).
